# 簡化流程規格 v0.1（草稿，待確認）

> 狀態：只有規格，尚未改程式。標 ❓ 的項目需要實測，標 🟡 的項目待營運者決定。
> 取代對象：`docs/QUEST-JOURNEY.md` 的 27 關建置流程。

## 1. 目標

| 原則 | 做法 |
| --- | --- |
| 三段流程 | ① 定位（2 題）→ ② 建置（固定範本）→ ③ 在自己的 OA 跟秘書對話修改 |
| 建置不用 AI | 部署固定範本，不產生程式碼，不扣點，每次結果相同 |
| 設計即設定資料 | 選單、卡片、回覆、秘書功能都存成客戶資料庫裡的一份設定，改了立即生效 |
| 平台不長期連著客戶 | 建置完成後，平台不保留客戶的 GitHub／Supabase／LINE 存取權 |
| 修改走 API、扣點數 | 客戶的 OA 呼叫平台 API，費用從該客戶的點數錢包扣 |
| 金鑰不經過平台 | 瀏覽器先加密，平台只轉寫密文到客戶 repo 的 Secrets |

## 2. 建置後，平台與客戶之間還剩什麼

| 項目 | 存在哪 | 說明 |
| --- | --- | --- |
| API 金鑰（`aprico_…`） | 明文只在客戶的 Supabase secrets；平台只存雜湊 | 現有 `line_oa_kit_runtime_keys`，可撤銷 |
| 點數錢包、用量紀錄 | 平台 | 現有 `line_oa_kit_points_wallets`、`line_oa_kit_ai_usage` |
| 客戶的設定資料、對話、會員資料 | 客戶自己的 Supabase | 平台不保存 |
| GitHub App 授權 | 建置完成後提示客戶可以移除 | 之後更新範本時才需要再授權一次 |

建置頁要用白話說清楚這一點：「建好之後，Aprico 不會連著你的帳號。你在自己的 OA 請秘書幫忙時，才會把那一句話和目前的設定送到 Aprico 處理，並扣你的點數。」

## 3. 階段一：定位（2 題）

| # | 問題 | 選項 | 對應現有資料 |
| --- | --- | --- | --- |
| 1 | 這個帳號要做什麼？ | 官方帳號選單／個人秘書／兩者都要 | `secretary.direction`：`oa`／`records`／`both` |
| 2 | 用一句話說你的目標 | 自由輸入，上限 200 字 | 現有 `goal`，交給 AI 預填（`build-prefill.ts`） |

- 依第 1 題給預設範本：選單用 `menuPresets`，秘書用 `recordPresets`（行程、收支、待辦、生活紀錄）。
- 原本 6 題需求（服務對象、目的、情境、成功條件、失敗處理、轉人工）不再問。失敗處理與轉人工給預設文字，之後在對話裡改。
- 這一段不扣點。❓ 第 2 題的 AI 預填目前是否計費，改之前要再確認。

## 4. 階段二：建置

### 客戶要做的事

| # | 動作 | 取代原本的關卡 |
| --- | --- | --- |
| 1 | GitHub：按授權（GitHub App） | 登入、建專案、填網址、貼 Token 共 4 關 |
| 2 | Supabase：貼 1 個 Access Token | 登入、建專案、填網址、貼 Token 共 4 關 |
| 3 | LINE Messaging：貼 Channel ID、Channel Secret | 原 3 關；長效 Token 那關拿掉 |
| 4 | LINE Login：貼 Channel ID、Channel Secret，並把狀態改成 Published | 原 3 關 |
| 5 | 按「開始建置」 | 核對、自動建置 2 關 |
| 6 | 到 LINE 後台開啟 Webhook、關閉自動回應 | 原 1 關（LINE 沒有 API，省不掉） |
| 7 | 加自己的 OA 好友，傳綁定碼 | 取代手動輸入 `runtimeOwnerId` |

27 關變成 7 個動作，其中要貼的值共 5 個。

### 系統做的事

1. 平台用 GitHub App 取得客戶 repo 的加密公鑰；瀏覽器用它加密 Supabase Token 與 LINE 的 4 個值；平台把密文寫進 repo 的 Actions Secrets。
2. 平台把固定範本寫進 repo，觸發 workflow。
3. 客戶 repo 的 Actions 執行：建立或選用 Supabase 專案、建資料表、部署 Webhook、設定 secrets、設定 LINE Webhook 網址、建立 LIFF、建立圖文選單、寫入初始設定資料、發布 Pages。
4. 平台讀 repo 裡的狀態檔顯示進度。
5. 完成後發一組 6 位數綁定碼（10 分鐘有效）。客戶在自己的 OA 傳這組碼，Webhook 把傳訊者記為擁有者。

LINE 的使用者 ID 每個 Provider 都不同，所以客戶在 Aprico 的 ID 不能直接當成他自己 OA 裡的擁有者 ID，必須用綁定碼。

### 固定範本的內容

| 元件 | 內容 |
| --- | --- |
| 設定資料 | 一份 JSON，格式沿用現有 `Draft`（`src/model.ts`），存在客戶的 Supabase |
| Webhook | 驗簽章 → 讀設定 → 選單回覆、卡片、秘書紀錄；擁有者的修改指令轉給平台 API |
| LIFF 頁 | 讀設定顯示卡片與表單 |
| 圖文選單 | 依設定的格數、配色、印花產生 |

❓ 待實測：GitHub App 能否代客戶建立 repo。不行的話，客戶多按一次「從範本建立」。
❓ 待實測：GitHub App 需要新增 Actions、Secrets、Workflows 寫入權限，現有已安裝的使用者要重新同意。

## 5. 階段三：在自己的 OA 跟秘書對話修改

```
擁有者在自己的 OA 說：「第 3 格改成預約，按了回一張卡片」
  → 客戶的 Webhook 確認是擁有者 → 呼叫平台 API（附上那句話＋目前設定）
  → 平台 AI 回傳：修改後的設定＋白話摘要＋這次會扣幾點
  → 秘書回覆：「我會把第 3 格改成『預約』，按下後回一張卡片。這次扣 X 點，要套用嗎？」
  → 擁有者回「套用」→ Webhook 寫入自己的設定資料，必要時重建圖文選單
```

- 可以改的範圍（v1）：選單格數與每格內容、配色與印花、回覆文字與卡片、秘書的紀錄項目與回覆格式、失敗處理與轉人工文字。
- 不在 v1 範圍：新增 LIFF 頁面類型、接外部服務、自訂資料表。這些要改範本程式，另外處理。
- 平台回傳的設定一律經過現有的 `validateDraft` 檢查，Webhook 套用前再檢查一次；不合格就不套用、不扣點。
- 只有擁有者能進入修改；一般好友的訊息走正常服務。
- 平台 API 不保存客戶的設定與對話內容，只記錄用量。
- 沒按「套用」就不寫入。取消時是否扣點見第 6 節。

現有的「在 Aprico 官方 LINE 對話設計」（`chat-design.ts`）保留為建置前的試用與設計；建置後的修改都在客戶自己的 OA 進行。

## 6. 點數

### 現況（程式碼）

- 每購買一次點數方案（NT$1,680）入帳 1,680 點。
- 扣點公式：`API 成本（美元）× 匯率 × 10`，也就是成本 NT$1 扣 10 點。
- 換算下來，1,680 點可用的 API 成本是 NT$168，**成本是售價的 1/10**。

### 目標：成本是售價的 1/5

把倍數從 10 改成 5（成本 NT$1 扣 5 點），1,680 點可用的 API 成本變成 NT$336。倍數寫在 `line_oa_kit_reserve_ai` 與 `line_oa_kit_settle_ai` 兩個函式裡，要一起改，並改成從費率表讀取，之後調整不用再改函式。

### 實測計畫（定價前要做）

| 操作 | 量什麼 | 次數 |
| --- | --- | --- |
| 秘書一般回覆 | 每則的 token 用量與成本 | 20 |
| 秘書紀錄（行程、收支、待辦、生活） | 同上，每種各測 | 各 10 |
| 修改設定（小改：一格文字） | 同上 | 10 |
| 修改設定（大改：整組選單） | 同上 | 10 |

輸出一張表：每種操作的平均成本、最高成本、在 ×5 倍數下各扣幾點、1,680 點大約能用幾次。再依這張表決定倍數與是否分級收費。實測會呼叫付費 API，執行前另外取得同意並先報預估費用。

🟡 待決定：
1. 擁有者看了修改提案但沒套用，要不要扣點？（AI 成本已經發生。建議扣，並在提案前先顯示預估點數。）
2. 一般好友使用秘書功能時，扣的是擁有者的點數。點數用完時秘書要怎麼回？（建議：對好友回預設文字，並私訊提醒擁有者。）
3. 建置本身（固定範本、不用 AI）的收費方式：沿用 NT$3,860 單一專案，還是調整？

## 8. 實作順序

每一步各開一個 PR，都不影響線上，直到營運者合併與部署。

1. 範本 repo：固定範本的 Webhook、LIFF、Actions workflow（在 `oaw-template`）。
2. 平台：GitHub App 寫入密文 Secrets 與觸發 workflow；綁定碼。
3. 前端：建置中心改成兩題＋7 個動作。動手前先提供畫面規格確認。
4. 平台 API：修改設定的端點；範本 Webhook 的擁有者修改流程。
5. 點數：倍數改為可設定，跑實測，定價。
6. 移除退場模組，更新文件與銷售政策草稿。

## 9. 已知限制

- LINE 的三件事沒有 API：建立 Login channel、改成 Published、開啟 Webhook。
- 平台可以寫入客戶 repo 的 workflow，理論上有能力讀到 Secrets。緩解：範本公開、固定版本、建置完成後提示移除 App 授權。
- 修改設定時，那一句話與目前的設定會送到平台與 AI 供應商處理；建置頁與銷售政策要寫明。
- 現有文件寫明購買內容包含「5 次 AI 建置」。改成固定範本後，已購買的使用者權益要怎麼處理，需要營運者決定。🟡
